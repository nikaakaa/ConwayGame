# 生命游戏实现说明

本文描述现有稀疏坐标实现。后续的统一四叉树、位图叶子与 HashLife 缓存方案见[混合演化核心设计](路径/混合演化核心设计.md)，尚未接入运行时。

## 规则与世界

每格检查八邻域，统一按 B3/S23 演化：死亡格有 3 个活邻居时出生；存活格有 2 或 3 个活邻居时存活；其余死亡。所有判断读取同一代，整代计算完成后统一发布。

世界只保存活细胞的 `int2` 坐标，x 向右、y 向上，没有固定宽高、环绕或离屏裁剪。空白区域不占用棋盘数组。无预设边界仍受整数范围、内存和算力限制；没有 AOI，离屏细胞继续演化。

八种内置结构统一来自 `LifePatterns.Items`，只提供初始坐标与资料，不播放预制动画、不自动识别周期。自定义结构与内置结构共用 `LifePattern` 模型。独立图案的周期与方向见 [README](../README.md#预置图案)；多个图案碰撞后可能改变行为。

## 数据归属与调用链

默认 ECS World 中只有一个棋盘 Entity，由 `LifeSimulationSystem : ISystem` 创建。`LifeSettings` 保存速度，`LifeState` 保存运行状态、代数、累计时间与显示版本。`DynamicBuffer<AliveCell>` 是世界的唯一正式数据源，数量直接取缓冲区长度。

1. `LifeController` 接收键盘、工具栏和棋盘指针事件，维护单格或结构笔刷选择。左键逐格追加存活的 `SetCell`，结构笔刷把相对坐标加到鼠标世界格子上；右键追加死亡的 `SetCell`。
2. `LifeSimulationSystem.OnUpdate` 顺序消费 `LifeCommand` 缓冲区，再根据运行状态累计 ECS 时间，以 `1 / GenerationsPerSecond` 的间隔推进。
3. System 调用 Burst 作业计算整代，完成后写回活细胞缓冲区。
4. `LifeView.LateUpdate` 只读已发布坐标，通过像素作业生成黑白纹理并上传显示。

`SetCell` 线性查找正式坐标，新增时保持唯一，删除时使用 `RemoveAtSwapBack`。单格绘制、结构盖章与擦除均用 Bresenham 补齐相邻采样点；重叠盖章不翻转细胞，编辑自动暂停并保留代数。离开棋盘后断开笔画。

System 只在初始化时读取 Block，不读取自定义文件。R 由控制器先提交 `Clear`，再把当前结构的坐标作为 `SetCell` 提交到原点，支持自定义结构；没有专用 `LoadPattern` 指令或图案索引字段。C 只清空、暂停和归零，Home 只恢复视野。

Space 控制运行，N 暂停并推进一代。速度范围为每秒 1–1000 代，默认 10 代；上下键翻倍或减半，按住每 0.12 秒重复，也可在工具栏直接填数值或使用倍速按钮。暂停、单步与调速清空累计时间，指令保持到达顺序。名称或速度输入框聚焦时停用键盘快捷键。

## 结构目录与保存

`LifePatternStore` 显式接收保存目录，初始化时创建目录。`Patterns` 包含八个内置对象的原始引用与目录中 JSON 生成的结构，内置坐标没有复制成第二份目录。

工具栏保存时，将当前正式活细胞缓冲区交给 `Save`。Store 对包围盒计算 `origin = min + (max - min + 1) / 2`，将每个坐标减去该中心，再写入 `Application.persistentDataPath/Patterns`。保存包含整个世界，空棋盘由保存按钮禁用。每次使用新 GUID 文件名，不覆盖已有结构，返回的 `LifePattern` 随即加入列表并被选为结构笔刷。

JSON 格式为 `{"name":"名称","cells":[{"x":0,"y":0}]}`，使用 `JsonUtility` 和 UTF-8 无 BOM。自定义结构的类别为“自定义”，周期为 0，表示未知，位移为零。`Reload` 重新读取目录中的 `*.json`；以后添加同格式文件后可通过工具栏刷新加载。

目录初始化、保存与刷新允许托管分配和磁盘 I/O，只在初始化或用户操作时执行。System 和像素作业不读文件，连续盖章直接使用已加载数组。

## 稀疏演化

设当前活细胞数量为 `L`、候选数量为 `C`，下一代数量为 `Lnext`，有 `C <= 9L`。System 持久复用四个原生工作容器：

| 容器 | 职责 |
| --- | --- |
| `AliveLookup` | 从正式缓冲区生成本代邻居查询索引 |
| `CandidateSet` | 对活细胞自身及八邻域去重 |
| `Candidates` | 连续候选列表，供并行索引访问 |
| `NextAlive` | 接收下一代计算结果 |

每代先准备容量，再用 Burst `CollectCandidatesJob : IJob` 建立索引与候选列表；随后调度 `EvolveJob : IJobParallelFor`，每个候选检查八邻域，通过 `ParallelWriter` 写入下一代。并行写入期间不扩容。`Complete()` 后才写回正式缓冲区、增加代数与 `Revision`。

这些容器是计算工作数据，不是另一份可编辑世界。同帧完成作业会产生同步等待；缓冲区的原生视图不跨扩容或下一帧持有。System 销毁时完成依赖并释放容器。

## 棋盘、工具栏与坐标

`LifeSceneBuilder` 装配相机、全屏 RawImage 棋盘、Input System EventSystem、控制器和视图。格子保持正方形，短边按屏幕比例显示。Game 内的 UI Toolkit 小工具栏位于左上角，提供笔刷与结构列表、演化控制、缩放、速度和结构存取；Tab 显示或隐藏。工具栏使用运行时创建的 Windows Microsoft YaHei 字体，不依赖项目字体文件或 TMP 资源。

`LifeView.TryGetCell` 将屏幕位置转到棋盘 RectTransform，确认在区域内后，根据整数窗口原点与可见格数向下取整。摆放、擦除和显示共用这份坐标转换，支持负坐标。中键拖动平移，滚轮保持鼠标下的世界格子不变；这些操作不改变演化状态。

默认视野以原点为中心，长边显示 128 格；缩放以两倍为一档，长边范围为 8–16384 格。滚轮使用鼠标锚点，工具栏提供缩放按钮。

视图固定复用一张 `1024 × 1024` 点过滤纹理与同尺寸 `NativeArray<Color32>`，始终显示完整 UV。CPU 像素作业先写黑底，再遍历全部活细胞：近处把一格填成多个白色像素，远处把多格映射到同一个像素，只要其中存在活细胞就显示白色。远景压缩只影响显示，正式坐标与演化精度不变，纹理不随世界范围继续增大。

作业完成后通过 `SetPixelData` 和 `Apply` 上传整张纹理，由 GPU 绘制 RawImage。世界 `Revision` 或视野变化时才重画，每帧最多上传一次。规则计算与像素生成均没有使用 Compute Shader。

## 成本与限制

通常哈希访问成本下，候选收集、演化和写回的期望工作量为 `O(L + C + Lnext)`，与图案之间的坐标跨度无关。哈希容器清空还受保留容量影响，小图案的调度与同步成本可能高于并行收益。

每个 `SetCell` 需要 `O(L)` 查找。设一次笔画经过 `D` 个新锚点，结构含 `K` 个活细胞，会生成约 `D × K` 条指令，查找成本随指令数与当前人口相乘。连续新增还会扩大后续扫描范围。缩远后，相同屏幕位移经过更多世界格子，进一步增加指令量。用户已反馈画笔卡顿；这是源码确认的复杂度热点，尚未测出各部分的耗时占比。

像素作业清理固定的 `1024²` 像素，并遍历 `L` 个活细胞；近景还需填充格子覆盖的像素。`SetPixelData` 将像素数组复制到纹理 CPU 数据，`Apply` 上传整张纹理。独立像素数组约占 4 MiB，纹理的 CPU 与 GPU 副本另计。没有 AOI，显示仍遍历离屏活细胞。

自动运行在同帧通过 `while` 追赶累计时间，多代计算会连续占用主线程。人口、目标速度和单代成本共同影响输入响应。当前调度没有每帧模拟工作预算，不能把速度上限视为实际吞吐量。

模拟、像素和拖绘稳态路径复用 ECS 缓冲区、哈希集合、候选列表及像素数组，不使用 LINQ、每代 `ToNativeArray` 或逐细胞托管对象。工具栏初始化、结构存取和原生扩容单独评估；容量保留使内存受历史峰值影响。速度上限只是控制范围，不能保证任意人口都能达到每秒 1000 代。以上不是已测量的 0 GC、吞吐量或加速结论。

## 文件与检查状态

正式入口为 `Assets/GameOfLife/Scenes/GameOfLife.unity`。运行时代码位于 `Assets/GameOfLife/Runtime/`：`LifeComponents.cs` 定义协议，`LifeSimulationSystem.cs` 消费指令与演化，`LifePatterns.cs` 提供内置结构，`LifePatternStore.cs` 负责结构存取，`LifeController.cs` 处理输入，`LifeView.cs` 处理坐标和纹理。`Editor/LifeSceneBuilder.cs` 提供场景装配菜单。

已记录一次 Unity CLI C# 编译通过（0 错误、0 警告）。原工具栏的 Play 初始化检查确认默认 World、1024 纹理与工具栏建立，初始 Block 为暂停的第零代、4 个活细胞、每秒 10 代和单格笔刷。已查看 1280 × 720 Game 截图，棋盘全屏，工具栏文字正常显示。EventSystem 射线检查确认工具栏先接收其区域的事件，棋盘中央直接命中 Board。这些记录不覆盖后续工具栏调整。

通过正式 `LifePatternStore.Save` 与 `Reload` 调用完成 4 格结构的 JSON 保存和重新读取，目录重新加载后包含八种内置结构与一个保存结构。此检查使用独立目录，不向用户结构目录写入示例数据。

升级 Burst 后曾因 Editor 持有旧原生编译器而使 Entities 初始化失败，保存并重启目标 Editor 后恢复。当时另有 Package Manager 路径错误与 Profiler 内存压力提示，未扩展处理。

补充的 CLI 缩放与拖绘组合检查，以及演化与编辑性能测量均遇到主线程命令超时，未取得可报告的性能结果。CLI 响应时间包含命令分发与动态编译，不能作为模拟或画笔耗时。未新增测试代码，连续鼠标操作、缩放边界、八种图案周期和完整操作仍由实际交互验收；尚无有效 Profiler 采样或前后性能对比。

混合核心仍处于设计阶段，没有验证 RLE 导入或真实 Life-in-Life 演化。后续测量范围、提交边界及与原 OpenSpec 规划的差异统一记录在[混合演化核心设计](路径/混合演化核心设计.md)。

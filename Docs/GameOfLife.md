# 生命游戏实现说明

## 规则与状态归属

世界统一按 B3/S23 演化：死亡格有三个活邻居时出生，活格有两个或三个活邻居时存活。计算只读取已完成的一代；跨代任务完成后统一发布新根和实际代数。离屏区域继续演化，世界没有固定宽高、环绕或 AOI。

`LifeSimulationSystem : SystemBase` 在默认 Entities World 创建一个棋盘 Entity。`LifeSettings` 保存目标代速，`LifeState` 保存运行状态、实际代数、累计待推进量与显示版本，`LifeCommand` 缓冲区保存有序输入。System 持有唯一的 `LifeWorld`；其原生节点池、已发布根和根的世界位置是正式棋盘数据。

`LifeShape` 使用长整数保存根位置，指针、选区、预设文件坐标使用 `int2`。世界范围受整数类型、内存与算力限制。人口直接读取根节点的 `long Population`。

## 输入到显示的调用链

1. `LifeController` 接收鼠标、键盘与工具栏操作，将一次拖动提交为一条 `CellStroke` 或 `PatternStroke`。结构携带已编译的树形快照。
2. `LifeSimulationSystem` 顺序消费指令，按 Bresenham 保留完整世界格采样，调用 `LifeWorld` 批量修改叶子。框选删除提交闭区间 `ClearArea`。
3. System 按目标速度选择二次幂跨代请求，调用世界模块续跑 HashLife；完成后发布根，并增加实际完成的代数。
4. `LifeView.LateUpdate` 取得已发布树，交给 `LifeRasterJob` 按窗口裁剪和缩放绘制，再上传固定纹理。
5. 工具栏读取控制器的 `State`、`Speed` 与 `Population`，通过相同控制器方法发起操作。代数与人口控件复用数字字符串。

单格、擦除和结构盖章均保留连续补点与重叠合并语义；编辑自动暂停并保留代数。一次长笔画最多处理 2048 个锚点，并在时间预算到期时保留当前坐标与 Bresenham 误差，下一帧继续。其后的单步、清空等命令保持顺序。离开棋盘中断当前笔画。

单步精确推进一代。自动推进遇到新命令时取消未发布的任务，已发布棋盘保持完整；已发起的显式单步完成后再处理后续指令。C 清空、暂停并归零，R 清空后在原点盖章当前预设，Home 只恢复视野。

速度范围为每秒 1–1,073,741,824 代，默认 10；这是请求值，实际吞吐由图案和算力决定。累计待推进量最多保留一秒的目标量。暂停、单步和调速清空累计量。

## 位图叶子与 HashLife

`LifeWorld` 使用 16×16 位图叶子，每叶四个 `ulong`，每行占 16 位。相同叶子按内容去重，分支按西南、东南、西北、东北四个子节点去重，形成共享四叉树。48 字节的 `LifeNode` 在叶子位图与分支索引之间复用存储。

单格修改先合入按叶子位置索引的原生暂存表，提交时重建受影响路径。结构摆放通过子树平移与按位 OR 合并；对齐子树可以直接复用，未对齐时按位图区域读取和组合。保存、复制由用户显式触发时才收集活细胞坐标。

演化缓存的键为 `(nodeId, exponent)`，表示推进 `2^exponent` 代后得到输入安全中心的一半大小结果。缓存未命中时建立九个重叠子区域，再组合第二阶段；到 32×32 输入时，以位运算计算八邻域，最多推进八代并返回中心 16×16。输入边界到安全中心的距离保证外部影响不会提前进入结果。

递归过程使用原生任务栈保存，`ContinueAdvance` 每批处理 128 份工作并通过 Burst Job 执行。重复结构共享节点及演化结果；混沌区域产生更多缓存未命中与位图计算。混合核心的算法依据和取舍见[核心设计](路径/混合演化核心设计.md)。

System 在约 2 ms 的帧预算内连续处理小批次。预算在批次之间检查，因此单次原生扩容、回收批次或大型盖章仍可能超过预算；它不是硬性帧耗时保证。当前算法和共享缓存由单写入者处理，Job 在返回前完成。

节点数达到回收阈值时分帧标记、清扫并复用空槽。根包括当前世界、已加载预设、排队结构命令、编辑状态与在途推进任务；存活节点 ID 不移动，可达缓存结果一并保留。原生容器保留容量，空槽复用不等于立即归还全部内存。

保存、导入、刷新或删除结构时，`LoadPatterns` 同步完成正在进行的回收，再编译预设并更新可用树形快照。这是显式文件操作的等待成本，不受常规演化的帧预算约束。

## 结构文件与边界

`LifePattern` 正式保存 `LifeTile[]` 和人口；八种内置结构的坐标、周期与位移保持原样，见 [README](../README.md#预置图案)。输入坐标在初始化或文件解析时打包为位图。

`LifePatternStore` 读取 `Application.persistentDataPath/Patterns` 中的 UTF-8 `.json`、`.rle` 和 `.cells`。初始化与显式刷新执行磁盘读取，演化不读文件。目录刷新先解析完整新列表，格式失败时保留已有列表，并由控制器向工具栏报告文件路径和原因。

保存有选区时取框内活细胞，否则取全部已发布棋盘。按活细胞包围盒中心转为相对坐标，继续写原 JSON 协议：
`{"name":"名称","cells":[{"x":0,"y":0}]}`。每次创建新的 GUID 文件。空世界或空选区只提示。

剪贴板导入支持 RLE、Plaintext 与 JSON。RLE 按游程直接写位图，解析时确认二状态 B3/S23；接受等价的 `S23/B3`、`23/3`、`Life` 写法，规则省略时按标准 Life 解释。不支持的规则、标记、宽高和游程会返回具体原因。RLE 行向下，转换后世界 y 向上；解析后按活细胞包围盒中心定位。

导入结构直接以 RLE 持久化；同名且位图集合相同的结构复用已有项。复制输出标准 RLE，按非空位图行排序和编码间隔，避免扫描整个空包围盒。保存和复制整张大型棋盘仍需显式遍历，初始化、导入导出和文件 I/O 允许一次性托管分配。

## 棋盘与 UI 边界

现有场景继续装配相机、全屏 RawImage、Input System EventSystem、控制器和 UI Toolkit。迁移保留场景引用，直接打开 `Assets/GameOfLife/Scenes/GameOfLife.unity` 即可。

视野默认以原点为中心显示 128 格，缩放范围为 8–67,108,864 格。滚轮保持鼠标世界锚点，中键平移；纹理始终为 1024×1024。树查询先剔除离屏节点，节点投影不超过一像素时依据人口合并显示，近景读取叶子位图；模拟仍保留逐格精度。

`LifeRasterJob` 直接写 `Texture2D.GetRawTextureData<Color32>()`，`Apply` 上传，由 GPU 绘制 RawImage。规则与像素生成使用 CPU/Burst；固定 RGBA32 纹理的单份像素数据约 4 MiB，大小不随世界范围增加。根、视野或叠加层变化时重画；稳定结构的代数变化无需重复上传。

灰色结构预览、深灰选区与虚线边框仍在同一像素作业中绘制。预览和选择不改变棋盘。工具栏与结构库由 UI 模块维护，样式位于 `Assets/GameOfLife/UI/`。结构库动态缩略图的展开、分配与帧成本属于单独的 UI 路径，本轮核心采样不覆盖该路径。

## 成本、证据与限制

树编辑成本随受影响叶子与路径增长，不再逐个命令扫描全世界人口。对齐、重复内容能获得更好的共享；高度混沌和未对齐的大型盖章需要更多实际计算。共享池的哈希访问、去重、扩容和回收均有成本，不能只以人口或使用 Burst 预测帧率。

当前 Unity CLI 编译通过，0 错误、0 警告。核心性能脚本覆盖百万细胞笔画、重复结构跨代、随机连续演化、混合图案与树渲染，并检查工作完成和输出。OTCA 输入还与独立参考引擎核对最终细胞指纹。数据、输入来源、测量条件和未覆盖范围统一保存在[性能记录](测试/生命游戏性能.md)。

高频核心路径的 0 B 记录仅适用于已测区间。没有旧核心同输入有效数据，因此不报告前后加速倍数；完整 Game 帧、结构库 UI、鼠标端到端行为和所有预置周期由实际交互验收。未新增 Unity 测试代码。

原 OpenSpec 仍描述旧坐标缓冲区，其待同步差异见[核心设计](路径/混合演化核心设计.md#与原-openspec-规划的差异)。本轮未执行 OpenSpec 工作流。

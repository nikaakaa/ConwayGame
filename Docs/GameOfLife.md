# 生命游戏实现说明

## 题目要求与实现

| 要求 | 实现与演示入口 |
| --- | --- |
| 生命游戏核心逻辑 | 全部图案使用 B3/S23，状态由 `LifeWorld` 统一保存，Entities System 调度 Burst 位图内核与 HashLife |
| 至少两种稳定状态 | 结构库中的 Block、Beehive，周期均为 1 |
| 至少两种震荡状态 | Blinker、Toad，周期均为 2 |
| 至少两种循环震荡状态 | 同时提供周期 3 的 Pulsar、周期 15 的 Pentadecathlon，以及周期 4 且产生位移的 Glider、Lightweight Spaceship，覆盖题目对原地长周期震荡或移动循环结构的两种理解 |
| 考虑实现效率 | 16×16 位图叶子、共享四叉树与跨代缓存、视野按需求值、分帧调度和显示；取舍见[核心设计](路径/混合演化核心设计.md)，实际结果见[性能记录](测试/生命游戏性能.md) |

结构首次写入后与用户结构一样可以删除或改名。初始坐标、周期和位移的源码位于 `Assets/GameOfLife/Runtime/LifePatterns.cs`，操作见 [README](../README.md#初始结构)。

## 规则与状态归属

世界统一按 B3/S23 演化：死亡格有三个活邻居时出生，活格有两个或三个活邻居时存活。所有区域属于同一个世界和时间线。视野及其因果依赖优先求值，离屏结果按请求补算；离屏细胞不会被裁掉或冻结。世界没有预设宽高或环绕边界。

`LifeSimulationSystem : SystemBase` 在默认 Entities World 创建一个棋盘 Entity。`LifeSettings` 保存目标代速，`LifeState` 保存运行状态、实际代数、累计待推进量与显示版本，`LifeCommand` 缓冲区保存有序输入。System 持有唯一的 `LifeWorld`，由初始树、不可变编辑版本 `Epoch` 和已发布代数组成正式世界。`LifeSnapshot(Epoch, Generation)` 标识版本；`LifeViewFrame` 只承诺其有效范围内的已完成内容。

`LifeShape` 使用长整数保存根位置，指针、选区、预设文件坐标使用 `int2`。世界范围受整数类型、内存与算力限制。工具栏通过 `LifePopulationSample` 读取最近完整载入或全图导出的人口样本，并提示样本代数；不会为统计每帧结算全图。节点上的 `Population` 供子树计算和远景绘图使用。

## 输入到显示的调用链

1. `LifeController` 接收鼠标、键盘与工具栏操作，将一次拖动提交为一条 `CellStroke` 或 `PatternStroke`。结构携带已编译的树形快照。
2. `LifeSimulationSystem` 顺序消费指令，按 Bresenham 保留完整世界格采样，调用 `LifeWorld` 批量修改叶子。框选删除提交闭区间 `ClearArea`。
3. `LifeView` 提供即时相机和整帧间隔。System 派生周边预加载范围，按实际相机尺度和目标速度选择跨代请求，由世界模块续跑区域与 HashLife 求值，完成后发布准确代数和有效范围。
4. `LifeView.LateUpdate` 固定已完成的 `LifeViewFrame`，通过 `LifeRasterJob` 分帧生成后台纹理。完整生成后交换纹理；拖动、缩放时由 GPU 立即重投影已有内容。
5. 工具栏读取控制器的 `State`、`Speed` 与 `PopulationSample`，通过相同控制器方法提交操作。保存和复制显式固定快照，由 System 续跑准确导出，完成后交给文件或剪贴板编码。

单格、擦除和结构盖章均保留连续补点与重叠合并语义；编辑自动暂停并保留代数。一次长笔画最多处理 2048 个锚点，并在时间预算到期时保留当前坐标与 Bresenham 误差，下一帧继续。其后的单步、清空等命令保持顺序。离开棋盘中断当前笔画。

单步精确推进一代。自动推进遇到新命令时取消未发布的任务，已发布棋盘保持完整；已发起的显式单步完成后再处理后续指令。C 清空、暂停并归零，R 清空后在原点盖章当前预设，Home 只恢复视野。

速度范围为每秒 1–1,073,741,824 代，默认 10；这是目标值，实际吞吐由图案和算力决定。`LifeSimulationPolicy` 按视野尺度与目标速度选择二次幂跨度，等待足够信用再请求；累计信用上限为 `max(两次期望跨度, 目标代数每秒 / 30)`。远景允许更大跨度，近景和显式单步保留逐代观察。暂停、单步和调速清空累计量，具体策略见[推进与交互响应](路径/混合演化核心设计.md#推进与交互响应)。

## 位图叶子与 HashLife

`LifeWorld` 使用 16×16 位图叶子，每叶四个 `ulong`，每行占 16 位。相同叶子按内容去重，分支按西南、东南、西北、东北四个子节点去重，形成共享四叉树。48 字节的 `LifeNode` 在叶子位图与分支索引之间复用存储。

单格修改先合入按叶子位置索引的原生暂存表，提交时重建受影响路径。结构摆放通过子树平移与按位 OR 合并；对齐子树可以直接复用，未对齐时按位图区域读取和组合。保存、复制由用户显式触发时才收集活细胞坐标。

预设的 `BuildShape` 在 Burst 作业中按 Morton 顺序排列位图叶块，再逐层拼接父节点。初始建树不再逐叶调用整棵树的盖章操作；返回的预设快照不替换当前棋盘。输入与排序临时空间约每叶块 56 字节，初始化完成后释放。

演化缓存的键为 `(nodeId, exponent)`，表示推进 `2^exponent` 代后得到输入安全中心的一半大小结果。缓存未命中时建立九个重叠子区域，再组合第二阶段；到 32×32 输入时，以位运算计算八邻域，最多推进八代并返回中心 16×16。输入边界到安全中心的距离保证外部影响不会提前进入结果。

区域查询和演化通过原生任务栈保存进度，System 按每批 128 份工作调用 `LifeWorld.Pump`。区域缓存按版本、代数和空间复用结果，内容缓存按节点与跨度复用 HashLife 内核结果。重复结构共享更多结果，混沌区域产生更多实际位图计算。算法依据和取舍见[核心设计](路径/混合演化核心设计.md)。

System 根据整帧间隔调整计算软预算，初始 1 ms、范围 0.25–4 ms；棋盘绘图另使用约 1 ms 软预算。时间在批次间检查，原生扩容、大型盖章和单批填充仍可能超限。Entities 承担棋盘状态与指令调度，Burst 编译位图和树运算；高频演化与共享缓存由一个写入者处理，Job 在返回前完成。当前没有把每个细胞建成 Entity，也不依靠 GPU 执行生死规则。

节点数达到回收阈值时分帧标记、清扫并复用空槽。根包括编辑版本的来源、已加载预设、排队结构命令、在途求值、固定导出快照和跨帧绘图树；存活节点 ID 不移动，可达缓存结果一并保留。原生容器保留容量，空槽复用不等于立即归还全部内存。

存入、导入、改名、删除结构或载入世界时，`LoadPatterns` 同步完成正在进行的回收，再编译预设并更新可用树形快照。这是显式文件操作的等待成本，不受常规演化的帧预算约束。载入存档或地图时，世界结构临时加入这份快照集合；等待中的盖章指令本身也是回收根，应用前不会被回收。

## 结构文件与边界

`LifePattern` 正式保存 `LifeTile[]` 和人口；八种初始结构的坐标、周期与位移保持原样，见 [README](../README.md#初始结构)。输入坐标在初始化或文件解析时打包为位图。

`LifePatternStore` 是唯一的结构库，读取 `Application.persistentDataPath/Patterns` 中的 UTF-8 `.json`、`.rle` 和 `.cells`，按文件名排序；新文件以时间戳开头，顺序即创建顺序。库中没有内置与自定义之分：首次使用把 `LifePatterns` 的八种基础结构写成普通 RLE 文件并留下 `.seeded` 标记，此后同样可以改名和删除；库被清空时重新写入，删除也保留最后一个结构，保证盖章和重置始终有可用结构。

打开结构库时比较目录签名（文件名、修改时间、大小），只有外部改动才重新解析；库自身的写入同步更新签名。改名只改写文件中的名称字段并保留路径，因此位置不变；结构对象不可变，改名返回新对象，控制器按对象或名称把当前结构对应回库中。演化不读文件，格式失败时保留已有列表，并由控制器提示文件路径和原因。

收录的大型结构作为地图提供。`Assets/StreamingAssets/LifePatterns/` 中的 16 份复杂 RLE 由 `LifeWorldStore` 管理，支持 `.rle` 与 gzip 压缩的 `.rle.gz`，盖章结构继续由 `LifePatternStore` 管理。打开地图列表只读目录、`maps.json` 索引与预览 PNG，不读取地图文件；索引和预览由 `Tools/MapPreviews/generate_previews.py` 离线流式扫描生成。脚本同样读取普通与 gzip RLE，预览最长边 128 像素；`metaglider-0e0p.rle.gz` 对应 `metaglider-0e0p.png`。缺少索引或预览时显示文件名与统一图标。

选中地图后，`LifeWorldStore` 才在后台线程读取文件，并按扩展名解压 gzip。普通文件与解压后的 UTF-8 RLE 文本统一交给 `LifePatternText` 解析，再回到主线程编译进模拟，期间显示载入画面。解析不调用 Unity API，结果不缓存。gzip 减少仓库和磁盘中的文件体积，载入时仍需完整 RLE 文本与解析后的位图，随后还要构建世界树，这些内存与计算成本仍然存在。图案涵盖飞船工厂、繁殖器、灰船、素数筛、图灵机、空间填充器和完整 Life-in-Life，来源和许可见[素材记录](参考/复杂结构来源.md)。

存档同样由 `LifeWorldStore` 管理，与地图共用“列表项只有名称与缩略图、选中才在后台解析”的流程。每个存档是 `Application.persistentDataPath/Saves` 下同名的 `.rle`、`.json`（名称）与 `.png`（`LifePreviewPng` 生成，与地图预览同一格式）。保存先用 `CollectCellsAsync` 固定请求时的世界版本，System 在后续帧续跑精确求值与细胞收集；主线程完成导出后，RLE 编码、写文件与缩略图在后台任务中完成。完成后主线程刷新列表，若保存期间没有换世界，当前世界归属该存档。刷新列表时路径与名称不变的存档沿用原列表项。RLE 以 `#C life-anchor x,y` 记录世界左上角（最小 x、最大 y）。载入时用记录的左上角减去解析后结构自身的左上角得到盖章锚点，不依赖 RLE 的居中与 y 翻转规则；没有该记录的外部文件按原点摆放。存档按世界文件的修改时间从新到旧排列，改名只写名称文件，顺序不变。载入存档或地图都先清空再盖章，代数从零开始，暂不恢复代数。`LoadPatterns` 的编译仍在主线程同步执行，因此工具栏先显示载入画面、等两帧确保已绘制，再调用载入。

存入结构时有选区取框内活细胞，否则取全部已发布棋盘。按活细胞包围盒中心转为相对坐标，继续写原 JSON 协议：
`{"name":"名称","cells":[{"x":0,"y":0}]}`。每次创建新文件，以默认名存入后由结构库进入改名。空世界或空选区只提示。

剪贴板导入支持 RLE、Plaintext 与 JSON。RLE 按游程直接写位图，解析时确认二状态 B3/S23；接受等价的 `S23/B3`、`23/3`、`Life` 写法，规则省略时按标准 Life 解释。不支持的规则、标记、宽高和游程会返回具体原因。RLE 行向下，转换后世界 y 向上；解析后按活细胞包围盒中心定位。

导入结构直接以 RLE 持久化；同名且位图集合相同的结构复用已有项。复制输出标准 RLE，按非空位图行排序和编码间隔，避免扫描整个空包围盒。保存和复制整张大型棋盘仍需显式遍历，初始化、导入导出和文件 I/O 允许一次性托管分配。

## 棋盘与 UI 边界

现有场景继续装配相机、全屏 RawImage、Input System EventSystem、控制器和 UI Toolkit。迁移保留场景引用，直接打开 `Assets/GameOfLife/Scenes/GameOfLife.unity` 即可。

视野默认以原点为中心显示 128 格，缩放范围为 8–67,108,864 格。滚轮保持鼠标世界锚点，中键平移；即时相机负责命中与输入，已完成纹理负责显示。相机派生 3.5 倍边长的周边预加载范围，棋盘以 3584² 双缓冲分帧生成并由 GPU 重投影；预览使用独立 1024² 覆盖层，白色活细胞通过 alpha 合成遮挡灰色预览，选区虚线使用独立 Graphic。

CPU 像素共 102 MiB，GPU 存储另计；像素尺寸不随世界跨度扩张。按树深度合并显示只降低显示精度，模拟仍保留逐格精度。相机移动不重启在途绘图，完整纹理完成后交换。有限周边缓存仍可能被连续多档缩放或远距离移动越过；职责和软预算见[核心设计](路径/混合演化核心设计.md#按缩放显示)。

灰色预览与深灰选区由覆盖层像素作业绘制，虚线边框由 `LifeSelectionGraphic` 生成独立网格。GPU 按图层合成，预览不读取棋盘像素判断遮挡。预览和选择不改变棋盘。

UI 由 `LifeEditorToolbar` 统一装配，样式位于 `Assets/GameOfLife/UI/`。启动先显示 `LifeStartScreen`：背景为独立定长网格上演化的 Gosper 枪，越界细胞丢弃，不影响正式世界；菜单为返回（从编辑界面回来时）、新世界、继续、存档、地图。存档与地图复用 `LifePatternLibrary` 浮层，未提供处理的操作不显示按钮，地图只读。

编辑界面的图标均由 `LifeCellIcon` 用与棋盘相同的方块绘制，颜色取 USS 自定义属性 `--cell-color`，只有暗灰与白两种状态。图标形状统一由 `LifeIcons` 提供，一个形状只表示一种操作。滑翔机随代数切换相位并负责收起与展开；悬停提示不放在图标下方以免被光标遮挡：图标行与二级的提示和操作结果共用一级图标行末尾的位置（操作结果优先），选区操作条与浮层的提示放在上方。一级只有演化、编辑、世界三组，全部点击展开二级，再点或 Esc 收起，鼠标移开不收起；编辑图标显示当前工具，盖章时为结构缩略图。Esc 由工具栏逐层处理：收起二级、取消选区、退出盖章回到之前的工具；关闭浮层的同一帧不再继续。选区操作条在拖动中隐藏，松手后提供存入、复制、删除。载入使用开始界面的载入画面；保存在后台进行，只用提示行报告进度。开始界面、任一浮层或帮助打开时，控制器快捷键统一停用。界面以 1080 像素高为 1 倍，运行时复制面板设置按窗口高度放大，小窗口保持 1 倍。

结构库缩略图通过 `LifePatternBitmap` 的 Burst 作业从位图叶块计算边界并生成纹理。整个叶块落在同一像素时只写一次；大型静态预览不展开逐格数组或 `HashSet`。不超过 2000 活细胞的小图案保留原有动画。浮层刷新按结构对象复用缩略图，增删改只为新对象生成。浮层只有网格与底部状态栏，网格缩略图即预览，不再为选中项单独生成大图。已核对八份新增素材的缩略图像素，百万级样本的五次构造耗时见性能记录；完整 UI 帧成本另计。

## 成本、证据与限制

树编辑成本随受影响叶子与路径增长，不再逐个命令扫描全世界人口。对齐、重复内容能获得更好的共享；高度混沌和未对齐的大型盖章需要更多实际计算。共享池的哈希访问、去重、扩容和回收均有成本，不能只以人口或使用 Burst 预测帧率。

目标 Editor 的编译与性能记录已保存。Windows 发行构建成功，0 错误、3 警告，详见[构建与运行](路径/构建与运行.md)。核心性能脚本覆盖百万细胞笔画、重复结构跨代、随机连续演化、混合图案与树渲染，并检查工作完成和输出。OTCA 输入还与独立参考引擎核对最终细胞指纹。数据、输入来源、测量条件和未覆盖范围统一保存在[性能记录](测试/生命游戏性能.md)。

本机 Unity 的 `GC.GetAllocatedBytesForCurrentThread()` 对已知 1 MiB 分配也返回 0，因此旧采样的 0 B 不作为无分配证明。分配检查改用经正、空区间校准的 Unity `GC.Alloc` 主线程事件计数，具体范围见性能记录。完整 Game 帧、鼠标端到端行为和所有预置周期由实际交互验收。未新增 Unity 测试代码。

原 OpenSpec 仍描述旧坐标缓冲区，其待同步差异见[核心设计](路径/混合演化核心设计.md#与原-openspec-规划的差异)。本轮未执行 OpenSpec 工作流。

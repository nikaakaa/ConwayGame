# 构建与运行 Windows 版本

## 运行现成程序

现有 ZIP 对应源码提交 `2684a6c`，主菜单和游戏内世界菜单的退出按钮均显示“退出”。包含主菜单/游戏双场景、完整 `.rle.gz` 地图加载、巨构冷启动步长，以及 `673bd15` 的当前视野优先刷新与同代内容树复用。构建目标为 Windows x64、Mono、非 Development Build。

解压 `Builds/GameOfLife-Windows-x64.zip`，运行解压目录中的 `GameOfLife.exe`。本机未压缩的程序位于 `Builds/Windows-Release/GameOfLife.exe`。

保留 EXE 同目录的 `GameOfLife_Data`、`MonoBleedingEdge`、`D3D12`、`UnityPlayer.dll` 和其他附带文件。分发使用完整 ZIP。`*_BurstDebugInformation_DoNotShip` 是构建调试资料，未放入 ZIP。

程序先进入主菜单。选择“新世界”进入空棋盘，选择“地图”载入复杂结构，也可载入存档；游戏内可返回主菜单。程序包带有 `运行说明.txt`，完整操作见 [README](../../README.md#操作)。最大的 0E0P 地图仍有一分钟以上的首次解析和较慢的冷演化，当前实测范围及限制见[性能记录](../测试/生命游戏性能.md#最大巨构的加载与首次推进)。

存档和盖章结构保存在 `Application.persistentDataPath` 下的 `Saves` 与 `Patterns`，不写入程序目录。本机对应 `%USERPROFILE%/AppData/LocalLow/DefaultCompany/麦吉太文笔试/`。这些用户数据不随源码提交或发行包分发，重载存档后代数从零开始。

## 从项目构建

使用 Unity **6000.3.3f1**，安装 Windows Build Support。当前产物为 `StandaloneWindows64`、Mono 后端、非 Development Build，Burst 原生库随程序打包。

以下步骤使用本机已安装的官方 Unity CLI。CLI 会启动对应版本的批处理 Editor，并在构建后退出；不需要启动 Pipeline 服务。

1. 如果该工程正在运行，需要保留棋盘时先在世界菜单保存存档。
2. 退出 Play，等待原有导入、编译结束，再关闭该工程的 Editor。
3. 确认源码已提交，在项目根目录执行下列 PowerShell 命令。

```powershell
unity --json --non-interactive build "$PWD" `
    --target StandaloneWindows64 `
    --output-path "$PWD/Builds/Windows-Release/GameOfLife.exe" `
    --log-file "$PWD/Builds/release-build.log" `
    --provenance-path "$PWD/Builds/release-provenance.json" `
    --no-tail
```

4. 等待原命令结束，核对 CLI `success=true`、退出码为 `0`，来源清单的 `outcome=success`，以及日志中的 `Build Finished, Result: Success.`。构建失败时从原日志定位，不从部分输出目录分发。

```powershell
Get-Content -LiteralPath 'Builds/release-provenance.json' -Encoding UTF8 | ConvertFrom-Json
```

构建按 `EditorBuildSettings` 中的顺序包含 `Assets/GameOfLife/Scenes/MainMenu.unity` 和 `Assets/GameOfLife/Scenes/GameOfLife.unity`，启动时先进入主菜单，不带模板 SampleScene。`Tools/Game of Life/Create Demo Scenes` 会重新生成这两个场景并重写构建列表。输出在 Git 忽略的 `Builds/` 内，源码提交不包含可执行文件。命令生成 Windows 目录；发行 ZIP 由构建完成后的该目录生成，校验全部文件 CRC 后替换原 ZIP。

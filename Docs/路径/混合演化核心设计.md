# 位图与 HashLife 混合演化核心设计

## 状态与目标

`LifeWorld` 以初始树、不可变编辑版本 `Epoch` 与已发布代数定义唯一世界。位图叶子和 HashLife 仍为唯一演化内核；视野请求按需物化该世界的局部结果。调用方与调度见[实现说明](../GameOfLife.md)，实际采样见[性能记录](../测试/生命游戏性能.md)。

目标是可交互的生命游戏编辑器：连续绘制和盖章能够及时响应，支持随机混沌图案、重复电路、结构存取与外部图案导入。大规模目标包括真实 Life-in-Life，即底层细胞按 B3/S23 演化，组成能够计算另一层生命游戏的电路。

世界支持正负坐标、自动扩展与离屏按需求值。视野只决定先计算哪里，不裁掉离屏细胞；查询离屏区域时必须得到相同代数的准确结果。范围仍受坐标类型、内存和算力限制。

## 统一世界与计算路径

世界模块使用普通 C# 表达算法，并用原生节点池保存共享四叉树。`LifeSnapshot(Epoch, Generation)` 是正式版本身份；初始树和编辑覆盖确定未物化区域。相同位图叶子或相同四个子节点共享节点身份，细胞内容和子树关系不可变，缓存索引随结果写入更新。平移不改变节点内容。

每个编辑版本保存区域格网原点：初始版本沿用完整初始树的原点，后续编辑继承来源。请求覆盖、父区域查找、邻域聚合与缓存象限读取均相对该原点对齐，避免为了匹配世界零点而把已共享的大树拆成大量带位置的记录。格网原点只决定内部划分，不改变鼠标、存档或导出的世界坐标。

叶子保存 `16 × 16` 位图，上层节点引用四个子节点。底层内核接收包含邻域的区域并返回安全中心。节点人口供树运算与远景绘制使用；工具栏读取独立的历史人口样本，不为计数启动全图求值。

演化沿同一条路径执行：

1. 视图提交即时相机，调度派生周围的预加载范围并提交目标代数；区域缓存按编辑版本、代数、位置与尺度查找完整结果。
2. 未命中时按编辑基准代数对齐二进制时间切分，递归取得同一时刻、覆盖反向因果范围的输入。相对基准的第 130 代从第 128 代推进 2 代，第 132 代从第 128 代推进 4 代；相邻区域共享这些时间边界。跨越编辑发生时刻时读取父快照，再按顺序应用活、死与不修改三态覆盖。
3. 取得完整输入后调用原 HashLife 安全中心内核，按内容节点与步长复用演化缓存；到叶子仍用同一套位运算计算生死。
4. 在途窗口全部完成后发布 `LifeViewFrame`，其中包含快照、有效范围、内容树与显示版本；再接续处理最新窗口需求。离屏依赖保留在同一个世界，之后请求时继续求值。

演化结果统一保存在 `Cache`。`StoreResult` 是唯一写入点，同时更新分支节点的 `CachedExponents`，记录哪些 `2^e` 推进请求已有结果。推进先检查该索引，回收只标记或删除索引列出的实际条目，避免遍历所有可能的指数并查询不存在的缓存。索引复用分支节点第 32 至 39 字节，`LifeNode` 仍为 48 字节；这段空间在叶子中属于位图，叶子不读取缓存索引。

内容缓存、区域缓存和编辑版本的条目数由各自的插入、删除入口维护在原生状态中。调度器直接读取计数，不在每个批次调用会遍历已删除槽位空闲链的 `NativeParallelHashMap.Count()`。这些计数描述实际条目数量，与允许过时的人口参考不同。

重复结构可以共享节点和演化结果，混沌区域会产生更多实际叶子计算。调度依据是缓存命中情况，无需预先识别图案类别。整张棋盘只有一份正式世界数据，位图是树的叶子表示，不能让两套引擎分别维护可编辑状态。

区域结果是可回收的派生缓存，不能单独当作完整世界。尚未计算的区域不是死亡区域；不能给局部结果补零后继续演化。查询先反向扩展因果范围，在初始树和各编辑版本的活覆盖中查找真实活源；只有确认整个来源链都没有活源，才直接得到空结果。这样稀疏大图不会仅因粗包围盒相交而细分大片空白。连续播放复用已物化切面，同代编辑创建新身份，已固定的导出继续读取原快照。

相邻区域通过重叠输入取得完整邻域。以 `32 × 32` 输入为例，最多推进 8 代后返回中心 `16 × 16`，外部影响尚未进入该中心。不能独立推进互相缺少边界信息的分块，再把结果直接拼接。

混合结构仍有树查找、节点去重和缓存管理成本，不能保证纯混沌场景达到独立位图引擎的最高速度。叶子尺寸与缓存策略需要测量，不以使用 HashLife 或 Burst 作为性能证据。

## 输入、存储和显示职责

| 模块 | 输入、处理与输出 |
| --- | --- |
| `LifeController` 与工具栏 | 接收鼠标、键盘和工具选择，按即时相机换算世界坐标，提交整段笔画或结构摆放指令，读取已发布状态 |
| `LifeSimulationSystem` | 读取相机、帧间隔和速度，派生预加载范围，按预算处理命令、区域求值与导出；跨代步长仍取相机尺度，ECS 状态投影正式快照的实际代数 |
| 世界模块 | 持有唯一节点池、初始树、编辑版本、区域缓存和内容缓存，执行批量覆盖及可续跑区域/HashLife 求值 |
| `LifeView` | 持有即时相机并提供窗口需求与整帧间隔；将已完成的 `LifeViewFrame` 分帧生成纹理，以 `TextureBounds` 重投影旧图，并绘制鼠标与选区覆盖层 |
| `LifePatternStore`、`LifeWorldStore` 与格式读写模块 | 分别接收盖章结构、地图与存档，解析为同一套结构数据，不参与每代计算；解析结果交给控制器载入，进度与错误交给工具栏显示 |

MonoBehaviour 负责装配、Unity 生命周期和表现接入。Entities 保留棋盘状态与调度职责，Burst 用于位图内核；Jobs 包装 Burst 运算，当前以 `.Run()` 分批执行；节点池与演化缓存由一个写入者更新。

正式运行时不维护平铺的全世界活细胞列表。`Shape`、同步 `Population/GetCell/CollectCells` 与 `ContinueAdvance` 旧公开入口已经迁移；显示只读有效窗口，精确数据收集统一走显式异步导出。

### 连续绘制与结构盖章

控制器在单次输入事件中批量提交笔画，世界模块按叶子合并活/死覆盖。编辑以当前已发布快照为来源，取消未发布的自动推进并提交同代新版本。同代连续编辑合并覆盖，已被导出固定的旧版本保持不可变；跨代编辑保留准确的父版本。

单格笔刷保留 Bresenham 补点，连续盖章保留逐世界格锚点和重叠合并语义。批处理不得通过丢弃采样点改变画笔结果，也不得跨越单步、清空等指令重排操作。

大型结构使用子树平移与合并摆放，避免把全部细胞展开为逐格命令。相邻修改在同一叶子内合并处理，减少重复建立祖先节点的成本。实际成本仍随修改覆盖的区域增长。

空白编辑层可直接接收原点按 16 格对齐的输入树，避免稀疏大结构沿大片空白递归合并。非对齐锚点仍由原有合并逻辑重排叶块，保证后续单格绘制、擦除与绝对叶块坐标一致。

文件解析产生的全部叶块由 `BuildShape` 一次建树：按相对块坐标生成 Morton 编码、排序，再自底向上合并四个象限。每个已占用父节点只构建一次，不再对每个叶块反复从根部盖章。排序和拼树在 Burst 作业内执行，临时原生输入与排序空间约为每叶块 56 字节，用完即释放；建树只返回预设快照，不替换已发布棋盘。

### 预设和外部图案

存结构、复制与保存先调用 `CollectCellsAsync` 固定当前快照，再由 System 在后续帧继续 `Pump`。选区请求准确选区，全图请求该版本的有限传播支持；收集完成后才交给结构文件、剪贴板或世界存档编码。等待期间继续处理视野与有序编辑。导出数组属于请求时刻，随后播放、同代修改或换世界不改变它。

结构 JSON 按包围盒中心生成相对坐标。RLE 在接收边界先校验规则、尺寸和游程并扫描真实活细胞边界，再直接填充居中的叶块；已经居中的叶块直接打包，不为平移另建第二份大字典，也不复制整份 RLE 只为去除首尾空白。两遍扫描读取同一份已载入文本，完整世界仍一次载入，不采用磁盘分区流式加载。JSON、RLE 与 Plaintext 最终进入同一套世界与预设模型。

RLE 解析边界确认文件规则为 B3/S23，错误原因交给工具栏显示。内置结构、JSON 结构与 RLE 结构共用摆放逻辑。宏细胞文件格式不计入本轮已确定的功能。

解析边界已接入规则、尺寸和游程检查，控制器将具体错误交给工具栏；大型结构摆放使用树合并。

复杂示例以完整 RLE 保存在 `Assets/StreamingAssets/LifePatterns/`，当前经 `LifeWorldStore` 作为只读地图载入；盖章结构库继续由 `LifePatternStore` 管理。`LifeSession.LoadWorld` 把解析叶块直接交给同一世界模块建树，再排入既有清空和摆放命令。消费前由排队命令保留形状，消费后由世界版本保留；完整地图不加入盖章结构字典，解析用的托管叶块数组在载入流程结束后即可回收。主菜单负责载入界面与操作入口。作者、固定来源、许可和哈希见[复杂结构来源](../参考/复杂结构来源.md)。大型缩略图经 `LifePatternBitmap` 直接把叶块投影到像素，避免为静态预览展开全部活细胞；小图案保留已有动态预览。

### 按缩放显示

视图先剔除树中完全离屏的节点，再按缩放深度读取。节点投影小于一个像素时，根据其人口决定像素是否为白色；近景继续读取叶子位图。远景合并只影响显示精度，世界状态保持逐格精度。

`LifeView.Origin/VisibleCells` 是即时相机，`TextureBounds` 是前台纹理实际覆盖的世界范围。拖动或缩放立即修改相机，`PresentSurface` 取两者交集，调整棋盘子 RawImage 的 `RectTransform` 与 `uvRect`，由 GPU 重投影已有图像。新区域尚未完成时，旧图按新相机移动，旧纹理覆盖不到的部分显示黑底；这些空白不表示该处世界已经求值或全部死亡。

`LifeViewport` 从相机直接派生预加载范围：设一屏边长为 `C`，`PreloadOrigin = (Origin & ~(C / 4 - 1)) - C * 5 / 4`，`PreloadCells = C * 7 / 2`，即 3.5 倍边长。它按四分之一屏对齐，连续小幅拖动不会逐格建立新范围；没有额外的预加载窗口状态。区域面积为一屏的 12.25 倍，实际求值成本还取决于活源、因果范围和缓存复用，不能按面积比例直接推算。

当已完成纹理对应当前尺度、相机仍处于同一对齐区间时，四周预留至少一屏、至多一屏半，可容纳任意鼠标锚点的一档两倍缩小。这描述已完成缓存的几何覆盖；异步在途请求与绘图仍可能落后于相机。连续多档缩小、移出已完成范围或首次冷加载时仍可能显示黑底，待该范围求值和纹理生成完成后补齐。

命中、ghost、缩放锚点、连续笔画与选区工具栏统一使用即时相机。相机变化时重新换算静止鼠标的位置；中键拖动期间滚轮缩放会重置拖动的原点、尺度与指针基准，使下一次拖动沿新尺度继续。

棋盘使用两份 3584² 前后台纹理，把 3.5 倍边长的预加载范围映射到像素，在同尺度的一屏内保持 1024² 的纹素密度。`LifeViewFrame.Version` 有新内容且没有在途绘图时，视图固定本次 `rasterFrame`，以独立栈和 `LifeRasterProgress` 续跑 `LifeRasterJob`，显式传入 `TextureSize`。每批 `WorkBudget` 为 64，逐段清理像素并遍历树，每帧在约 1 ms 软预算内推进。相机移动或新版本发布不重启正在生成的图；整张后台纹理完成后才上传、交换前后台，并更新 `TextureBounds`，随后可以开始下一张已完成区域帧。

跨帧绘图只保存节点 ID 与工作进度，不持有跨帧 `NativeArray` 视图；每批 `.Run()` 重新读取 `simulation.Nodes`。绘图开始时通过 `LifeWorld.SetRenderRoot` 注册固定树，节点回收沿正式根协议保留它，纹理生成完成后解除该绘图根；前台显示由 GPU 采样已完成纹理。

显示从下到上依次为根 RawImage 黑底、1024² 灰色 ghost 与选区填充覆盖层、棋盘 RawImage、独立的 `LifeSelectionGraphic` 选区虚线。棋盘纹理把死细胞清为透明、活细胞绘为不透明白色，GPU 按 alpha 合成，使白色棋盘遮住下方预览和选区填充，虚线位于最上层。显示子层全部关闭射线检测。

覆盖层按即时相机绘制，使用独立工作栈且只遍历 ghost；选区虚线由 `LifeSelectionGraphic` 生成几何网格。相机、画笔预览或选区变化分别更新对应显示，完成棋盘纹理交换不会触发覆盖层重画；CPU 不读取棋盘像素判断预览遮挡，鼠标移动也不重新遍历整个可见世界。

三份 RGBA32 纹理的 CPU 像素数据合计 106,954,752 字节，即 102 MiB：棋盘前后台各 49 MiB，1024² 覆盖层 4 MiB；GPU 纹理存储另计，尺寸不随世界跨度扩张。覆盖层仍同步整幅清理、绘制和上传；棋盘的最终上传也同步执行。绘图预算与 System 模拟预算分别控制，单批填充或上传仍可能超出预算。编译及实际交互结果见[性能记录](../测试/生命游戏性能.md)，不能仅凭分帧或编译通过承诺 60 FPS。

## 推进与交互响应

单步精确推进一代，快进允许分解为可复用的跨代推进。画面每帧显示最新已完成状态，代数使用实际推进量，不能把一次跨代调用记成一代。

区域内部使用相对编辑基准的最低有效位选择跨度，结果不依赖“最近缓存恰好算到哪一代”。单代发布在 512、1024 等时间边界仍可能需要较大的内部时间块；显示跨度为一代不代表内部只计算一代，也不保证每一代耗时相同。

`LifeSimulationPolicy` 使用整帧间隔反馈计算软预算，初始为 1 ms，范围 0.25–4 ms。目标为 60 FPS 的帧周期；超出后快速减小计算份额，有余量时逐步恢复。它没有把旧 8 ms 常量换成固定高配额，也不保证 Editor 或整套 UI 达到 60 FPS。

相机尺度决定期望跨代量：128 格视野为一代，4096 格为 32 代，32768 格为 256 代，65536 格为 512 代，131072 格为 1024 代。预加载范围不参与步长选择。`MinimumSamplesPerSecond = 1` 使跨度同时受目标代数每秒限制，最终取二次幂；例如 1280 代/秒、131072 格相机采用 1024 代请求。按目标速度积累一次请求信用所需的模拟时间不超过约一秒，实际完成时间还受区域求值、回收与绘图影响，并非一秒的硬时限。这些跨度是当前视野和速度的期望上限。冷启动与编辑后先请求一代，只在完整推进发布后提高下一次允许的跨度，并按相对编辑基准的二次幂时间边界对齐；初始发布代数依次为 1、2、4、8……，热度达到后才采用期望跨度。暂停恢复保留已有热度。System 等待实际计划跨度的足够信用后发起请求；显式单步始终是一代。

累计信用上限为 `max(两次实际计划跨度, 目标代数每秒 / 30)`。算力不足时实际代数吞吐降低，不跳过真实演化；信用不无限积压。推进每批最多 128 工作，回收每批最多 1024 工作，时间在批次边界检查。单次原生扩容、大型盖章或一整批工作仍可能超过预算。

一次 Update 可以完成多次请求；同代刷新、暂停时的导出也继续 `Pump`。System 每帧均向 `SetViewport` 提交派生的预加载范围，包括显式单步期间。`SetViewport` 保存最新需求，正在执行的区域窗口先完成并发布，再接续请求最新范围；连续拖动不会反复清空在途窗口的求值栈。`CancelAdvance` 撤销未发布的未来推进后，若当前已发布代数的最新范围尚未完成，继续请求该代的区域。显式单步仍只推进一代，先完成后再处理后续命令。

节点和区域缓存共同触发同一套回收：两者条目总数达到 262,144 后启动首轮，后续阈值为 262,144 与回收后条目总数两倍中的较大值。这样稀疏世界即使内容节点很少，区域缓存增长仍能启动回收；存活缓存较多时也不会每帧重复启动。回收保留当前世界、已加载预设、排队盖章、在途推进及跨帧绘图引用，并沿实际缓存条目标记结果。`SetRenderRoot` 是视图注册绘图树的唯一入口，登记时经过已有标记屏障，`BeginCollection` 在每轮回收中标记该根；视图不另建保留集合。清扫仍遍历节点池的历史槽位，删除未标记节点及其缓存；整轮扫完后，通过 `FreeNodes.AddRange` 批量归还退休 ID，此前不复用 ID。

回收与业务交替执行：有运行、在途求值或排队命令时，先给回收约四分之一预算，再用剩余预算求值或消费命令；暂停且无工作时，回收可使用完整预算。普通运行中的画笔可取消未发布推进，显式单步仍先完成。续画即使遇到本帧期限已到，也至少处理一个锚点。

为允许这条调度，回收开始时固定清扫槽位上限；新节点直接保留到本轮结束，并标记其子节点，自身不加入待标记队列。重新取得尚未清扫的旧分支时，若已进入清扫阶段，先删除它可能引用已退休结果的旧缓存，再保留它；新缓存写入前保留键节点与结果。推进栈外等待父帧接收的结果由 `PendingResult` 显式保存，开始回收时也列入根。清扫前始终优先完成已有标记，退休 ID 仍在整轮完成后统一归还。以上操作由同一写入者串行执行。

回收可跨越更多帧，期间演化与画笔继续工作；本轮新节点至少保留到下一轮才可能退休，不承诺固定内存上限。跨代请求仍在全部完成后一次发布，因此冷计算也可能多帧保持同一代。`LoadPatterns` 只服务盖章结构集合的重建，仍同步排空正在进行的回收；整图载入直接建树并沿现有回收屏障与根协议保留。托管 `GC.Collect` 与节点池回收分别测量。

编辑来源、最新完成区域帧、跨帧绘图树、区域工作栈和排队/在途导出都参与同一引用协议。编辑祖先进入原生待标记队列，每个回收工作展开一个版本；该队列始终先于区域裁剪、版本清扫和内容清扫执行，回收期间新建的版本经过同一入队屏障。区域缓存需在节点 ID 复用前清理，派生历史不能全部永久列为强根。人口样本仅保存计数与来源身份，不为显示数字保留整图树。

区域索引按空间保留最新代数及其逐次清除最低有效位所得的时间祖先，并以完整请求为单位记录使用年龄，保留最近 64 个请求触及的空间项。同一次复杂请求的内部访问不会使自己建立的检查点过期；请求包括窗口变化、推进、刷新和显式导出。

HashLife 的重叠输入节点不一定属于当前画面树，仅保留输出会反复删除仍有复用价值的缓存键。分支节点在第 40 至 47 字节记录最近使用的回收轮次，仍为 48 字节，叶子不读取该字段。清扫前分帧扫描本轮固定槽位范围，把最近两轮回收使用过且持有演化缓存的输入节点列为保留根，再完成子树和结果标记；之后重置游标，进入原有清扫。弱驻留节点在清扫期重新取得时清理旧缓存的屏障保持不变。

保留近期缓存会增加存活节点与后续回收阈值，以内存换取减少重算。索引淘汰仍可能要求重建时间检查点；初始树和编辑来源仍在，求值结果不变。这套寿命规则不保证无重算或固定内存上限。

跨代编辑仍保留必要的来源链，完整保存不会自动把它压成新基底。此次祖先分帧只改变执行时机，不减少历史总量。回收启动时枚举在途栈、排队导出与预设根，导出数组生成，以及原生扩容仍有同步段；这些限制与软帧预算分开评估。

## 性能测量范围

测量覆盖以下场景：

- 连续单格绘制、擦除与重叠盖章，记录人口、结构大小、笔画长度和缩放。
- 不同人口与密度的随机图案，检查缓存未命中时的实际成本。
- 重复稳定结构、震荡结构与电路，分别记录冷缓存和预热后的表现。
- 混沌区域与重复结构相邻，覆盖跨块边界交互。
- 可复现的真实 Life-in-Life 输入文件，记录文件来源、人口、跨度和推进代数。

分别记录输入处理、正式编辑、演化、主线程等待、树查询、像素生成和纹理上传。记录交互帧耗时、实际代数吞吐、托管分配、节点数、缓存命中率、内存峰值与回收停顿。

高频模拟、绘制和编辑按 0 GC 目标实现，初始化、文件读写与原生容量增长单独统计。分配观测使用经已知分配和空区间校准的 `GC.Alloc` 主线程事件计数，事件数不代表字节数。首次初始化仍可能出现在首个冷请求区间，不能与后续稳态区间合并宣称无分配。0 GC 不代表帧率或吞吐达标。

前后比较使用相同输入、推进代数、缩放、编译配置和缓存条件，记录硬件及其他负载。每侧至少测量五次并交替安排，报告中位数和范围；只有顺序采样时，报告绝对结果，不给精确加速倍数。测量区间必须完成实际工作，并核对输出状态、代数与失败次数。CLI 调度或动态编译超时不算有效测量。

真实 Play 的被动观测同时读取运行状态、代数、节点回收状态和帧指标，先排除初始化与人手暂停。ProfilerRecorder 的句柄有效不代表已经收到样本，缺少样本的零值不能解释为零耗时。Editor 帧间隔包含等待，不能直接归因到模拟核心。

当前与历史证据见[性能记录](../测试/生命游戏性能.md)。旧整图实现的银河八宏步及显示器连续播放数据只说明当时版本；迁移后的视野完成、精确导出和实际 Game 帧率分别核对。局部先完成并不代表全图计算消失，全图导出需承担尚未完成的离屏工作。

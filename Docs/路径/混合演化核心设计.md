# 位图与 HashLife 混合演化核心设计

## 状态与目标

本文记录已接入的性能方案：`LifeWorld` 以共享四叉树保存正式棋盘，叶子使用位图，演化使用 HashLife 缓存与 Burst 内核。调用方与调度见[实现说明](../GameOfLife.md)，实际采样见[性能记录](../测试/生命游戏性能.md)。

目标是可交互的生命游戏编辑器：连续绘制和盖章能够及时响应，支持随机混沌图案、重复电路、结构存取与外部图案导入。大规模目标包括真实 Life-in-Life，即底层细胞按 B3/S23 演化，组成能够计算另一层生命游戏的电路。

世界继续支持正负坐标、自动扩展与离屏演化。范围仍受坐标类型、内存和算力限制，不以摄像机视野裁剪模拟。

## 统一世界与计算路径

世界模块使用普通 C# 表达算法，并用原生节点池保存共享四叉树。已发布的根节点、位置和代数确定当前棋盘。相同位图叶子或相同四个子节点共享节点身份，细胞内容和子树关系不可变，缓存索引随结果写入更新。平移不改变节点内容。

叶子保存 `16 × 16` 位图，上层节点引用四个子节点。底层内核接收包含邻域的区域并返回安全中心。节点记录人口，供工具栏和远景查询使用，避免每帧枚举所有细胞来计数。

演化沿同一条路径执行：

1. 根据节点身份和请求推进的步数查询演化缓存。
2. 命中时复用已计算的结果节点。
3. 未命中时递归计算重叠子区域，到达叶子后使用位运算计算生死。
4. 组合结果并记录缓存，整次推进完成后发布新根节点与实际代数。

演化结果统一保存在 `Cache`。`StoreResult` 是唯一写入点，同时更新分支节点的 `CachedExponents`，记录哪些 `2^e` 推进请求已有结果。推进先检查该索引，回收只标记或删除索引列出的实际条目，避免遍历所有可能的指数并查询不存在的缓存。索引复用分支节点第 32 至 39 字节，`LifeNode` 仍为 48 字节；这段空间在叶子中属于位图，叶子不读取缓存索引。

重复结构可以共享节点和演化结果，混沌区域会产生更多实际叶子计算。调度依据是缓存命中情况，无需预先识别图案类别。整张棋盘只有一份正式世界数据，位图是树的叶子表示，不能让两套引擎分别维护可编辑状态。

相邻区域通过重叠输入取得完整邻域。以 `32 × 32` 输入为例，最多推进 8 代后返回中心 `16 × 16`，外部影响尚未进入该中心。不能独立推进互相缺少边界信息的分块，再把结果直接拼接。

混合结构仍有树查找、节点去重和缓存管理成本，不能保证纯混沌场景达到独立位图引擎的最高速度。叶子尺寸与缓存策略需要测量，不以使用 HashLife 或 Burst 作为性能证据。

## 输入、存储和显示职责

| 模块 | 输入、处理与输出 |
| --- | --- |
| `LifeController` 与工具栏 | 接收鼠标、键盘和工具选择，提交整段笔画或结构摆放指令，读取已发布状态 |
| `LifeSimulationSystem` | 管理生命周期、命令顺序和推进任务，调用世界模块，在完成边界发布结果 |
| 世界模块 | 持有唯一节点池、根节点和演化缓存，执行批量编辑、位图计算与 HashLife 递归 |
| `LifeView` | 按窗口和缩放查询已发布的树，生成固定尺寸显示纹理 |
| `LifePatternStore`、`LifeWorldStore` 与格式读写模块 | 分别接收盖章结构、地图与存档，解析为同一套结构数据，不参与每代计算；世界载入与 UI 由另一方维护 |

MonoBehaviour 负责装配、Unity 生命周期和表现接入。Entities 保留棋盘状态与调度职责，Burst 用于位图内核；Jobs 只并行处理互不争写的输出，节点池与演化缓存由一个写入者合入结果。

控制器、保存模块、人口读取和棋盘视图已迁移到树。正式运行时不维护平铺的全世界活细胞列表，文件导出需要遍历时在用户发起的保存操作内完成。

### 连续绘制与结构盖章

控制器在单次输入事件中批量提交笔画，世界模块按叶子合并修改。编辑只重建受影响的祖先路径，未改变的节点与缓存继续复用。

单格笔刷保留 Bresenham 补点，连续盖章保留逐世界格锚点和重叠合并语义。批处理不得通过丢弃采样点改变画笔结果，也不得跨越单步、清空等指令重排操作。

大型结构使用子树平移与合并摆放，避免把全部细胞展开为逐格命令。相邻修改在同一叶子内合并处理，减少重复建立祖先节点的成本。实际成本仍随修改覆盖的区域增长。

文件解析产生的全部叶块由 `BuildShape` 一次建树：按相对块坐标生成 Morton 编码、排序，再自底向上合并四个象限。每个已占用父节点只构建一次，不再对每个叶块反复从根部盖章。排序和拼树在 Burst 作业内执行，临时原生输入与排序空间约为每叶块 56 字节，用完即释放；建树只返回预设快照，不替换已发布棋盘。

### 预设和外部图案

JSON 保存选区或整个已发布棋盘，按包围盒中心生成相对坐标。RLE 导入直接构造位图叶子与树结构，导入结构以 RLE 持久化；JSON、RLE 与 Plaintext 最终进入同一套世界与预设模型。

RLE 解析边界确认文件规则为 B3/S23，错误原因交给工具栏显示。内置结构、JSON 结构与 RLE 结构共用摆放逻辑。宏细胞文件格式不计入本轮已确定的功能。

解析边界已接入规则、尺寸和游程检查，控制器将具体错误交给工具栏；大型结构摆放使用树合并。

复杂示例以完整 RLE 保存在 `Assets/StreamingAssets/LifePatterns/`，当前经 `LifeWorldStore` 作为只读地图载入；盖章结构库继续由 `LifePatternStore` 管理。世界载入和界面修改由另一方负责，本轮核心优化不改变这条分工。作者、固定来源、许可和哈希见[复杂结构来源](../参考/复杂结构来源.md)。大型缩略图经 `LifePatternBitmap` 直接把叶块投影到像素，避免为静态预览展开全部活细胞；小图案保留已有动态预览。

### 按缩放显示

视图先剔除树中完全离屏的节点，再按缩放深度读取。节点投影小于一个像素时，根据其人口决定像素是否为白色；近景继续读取叶子位图。远景合并只影响显示精度，世界状态保持逐格精度。

RawImage 继续使用固定尺寸纹理，纹理不随世界跨度扩张。像素生成直接写纹理的原生 CPU 数据，避免独立像素数组到纹理的一次整图复制。GPU 仍负责最终绘制，CPU 生成像素和上传的成本分别测量。

## 推进与交互响应

单步精确推进一代，快进允许分解为可复用的跨代推进。画面每帧显示最新已完成状态，代数使用实际推进量，不能把一次跨代调用记成一代。

自动运行按约 2 ms 的时间预算连续处理小批次，推进每批最多 128 个工作，回收每批最多 4096 个工作，时间只在批次边界检查。尚未完成的工作保留进度，累计待推进量上限为约两帧的目标量，即每秒速度的 1/30，且不少于一代。算力不足或回收占用多帧时降低实际吞吐，低速下每次只推进一代。单次原生扩容、大型盖章或一整批工作仍可能超过预算。

节点和缓存管理也计入预算与内存统计。已占用节点达到 262,144 后触发首轮回收，后续阈值为 262,144 与回收后存活节点数两倍中的较大值。回收保留当前世界、已加载预设、排队盖章和在途推进引用，并沿实际缓存条目标记结果。清扫仍遍历节点池的历史槽位，删除未标记节点及其缓存；整轮扫完后，通过 `FreeNodes.AddRange` 批量归还退休 ID，此前不复用 ID。

进入回收分支后，该帧只处理回收，不执行推进或消费交互命令，Generation 和已发布棋盘保持不变。因此分帧回收仍可能造成连续多帧停在同一代，不能只用单帧 CPU 耗时判断交互是否流畅。缓存索引和批量归还减少回收工作，不改变这一调度规则。托管 `GC.Collect` 是另一种回收，测量时与节点池回收分别记录。

## 性能测量范围

测量覆盖以下场景：

- 连续单格绘制、擦除与重叠盖章，记录人口、结构大小、笔画长度和缩放。
- 不同人口与密度的随机图案，检查缓存未命中时的实际成本。
- 重复稳定结构、震荡结构与电路，分别记录冷缓存和预热后的表现。
- 混沌区域与重复结构相邻，覆盖跨块边界交互。
- 可复现的真实 Life-in-Life 输入文件，记录文件来源、人口、跨度和推进代数。

分别记录输入处理、正式编辑、演化、主线程等待、树查询、像素生成和纹理上传。记录交互帧耗时、实际代数吞吐、托管分配、节点数、缓存命中率、内存峰值与回收停顿。

高频模拟、绘制和编辑按 0 GC 目标实现，初始化、文件读写与原生容量增长单独统计。分配观测使用经已知分配和空区间校准的 `GC.Alloc` 主线程事件计数，事件数不代表字节数。首次初始化仍可能出现在首个冷请求区间，不能与后续稳态区间合并宣称无分配。0 GC 不代表帧率或吞吐达标。

前后比较使用相同输入、推进代数、缩放、编译配置和缓存条件，记录硬件及其他负载。每侧至少测量五次并交替安排，报告中位数和范围；只有顺序采样时，报告绝对结果，不给精确加速倍数。测量区间必须完成实际工作，并核对输出状态、代数与失败次数。CLI 调度或动态编译超时不算有效测量。

真实 Play 的被动观测同时读取运行状态、代数、节点回收状态和帧指标，先排除初始化与人手暂停。ProfilerRecorder 的句柄有效不代表已经收到样本，缺少样本的零值不能解释为零耗时。Editor 帧间隔包含等待，不能直接归因到模拟核心。

当前已有核心、完整 Life-in-Life、优化前后真实 Play 及回收对照证据，详见[性能记录](../测试/生命游戏性能.md)。缓存索引与批量归还减少回收工作量；实际播放在不同状态仍有约 0.09–0.15 秒的回收停代，不作精确改善比例。目标 Editor 的 Profiler 历史曾造成内存压力，停止并清理后重采，仍有 13–15 帧停代；回收与推进的互斥调度尚未改变。优化后重新完成八宏步、282,624 代连续核对，全部检查点匹配既有独立参考；整体演化吞吐改善尚未确认。

## 与原 OpenSpec 规划的差异

原变更 `add-dots-game-of-life` 仍规定坐标缓冲区为唯一正式世界，并排除空间分块、周期缓存和文件导入导出。该规划还保留早期的无工具栏、有限缩放和旧调速约定。

混合核心已调整正式数据源、分块演化、演化缓存、文件导入、交互调度和显示查询。现行 OpenSpec 尚待对应工作流同步。本轮未执行 OpenSpec 工作流，未修改其文档或任务状态。
